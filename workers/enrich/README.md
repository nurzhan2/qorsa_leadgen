# enrich

Обогащение лидов контактами **с сайта самой компании**. Часть источников
(особенно `workers/hh`) знает домен компании, но не знает ни email, ни
телефона, а лид без контакта бесполезен. Этот воркер берёт из ядра такие
компании, заходит на их сайт, читает главную и пару страниц «Контакты / О нас»
и возвращает в ядро то, что компания **сама публично опубликовала**.

Воркер полностью самостоятельный: свои `requirements.txt`, `.env`, README и
тесты. Ни ядро, ни другие воркеры его не импортируют, и он их тоже.

---

## Как работает

```
ядро ── GET /api/v1/companies/pending-enrich?limit=50 ──▶ воркер
        (есть domain, нет email или phone, ещё не пробовали; самые горячие лиды первыми)

для каждой компании (не больше ENRICH_CONCURRENCY сайтов одновременно):
  1. домен → https://домен/   (не открылся → http://домен/)
  2. /robots.txt этого сайта: если главная запрещена, на этом всё
  3. главная → email / телефоны / мессенджеры + ссылки «Контакты», «Связаться», «О нас» (до 3)
  4. эти страницы по очереди (каждую сначала сверяем с robots.txt);
     останавливаемся, как только нашлось всё, чего компании не хватало
  5. выбираем лучший email, до 3 телефонов, WhatsApp/Telegram

воркер ── PATCH /api/v1/companies/{id}/contacts ──▶ ядро
        {email, phone, messenger, enrichNotes}, отправляется ВСЕГДА, даже если ничего не нашли
```

Ядро (`ContactEnrichmentService`):

- заполняет **только пустые** поля. Email/телефон, которые дал источник
  (2GIS, OSM, HH…), никогда не перетираются значением с сайта;
- **всегда** ставит `raw.enrich_attempted = true` и `raw.enrich_at`, чтобы
  сайт, где ничего нет, не обходили заново при каждом запуске;
- прогоняет телефон через тот же `PhoneUtil`, что и ingest (разбить,
  нормализовать, выбрать номер для звонка, классифицировать), и
  **пересчитывает score**. Появившийся контакт даёт «+10 есть контакт+гео»,
  мобильный ещё +15, а если есть только 8-800, то −10;
- пишет `raw.enrich_filled` (что именно заполнено) и `raw.enrich_notes`
  (откуда взято).

В Google Sheets email попадает в существующую колонку **Email**, а в
**«Причина»** добавляется пометка, например:
`есть контакт+гео | Контакт с сайта: email, телефон (email с /kontakty/; телефон с главной)`.

## robots.txt: обязательно, не опционально

Перед **любым** запросом к сайту читается его `/robots.txt`. Путь под
`Disallow` не запрашивается вообще: страница пропускается, а в
`enrichNotes` появляется «robots.txt закрыл страниц: N». Если закрыта
главная, сайт не обходится.

Реализовано по **RFC 9309**, собственным парсером (`robots.py`), а не
через `urllib.robotparser`. Стандартный парсер понимает только префиксы: не
знает `*` и `$` и берёт первое совпавшее правило. RFC и все крупные
краулеры используют wildcard и правило «побеждает самое длинное совпадение».
Частые на реальных сайтах `Disallow: /*?sort=` или `Disallow: /*.pdf$`
stdlib молча проигнорировал бы, то есть мы ходили бы ровно туда, куда
просили не ходить.

| Что | Как |
|---|---|
| Группа | ищем группу, где `User-agent:` совпадает с нашим токеном `qorsa-leadgen-enrich` (регистр и `/версия` не важны); если такой нет, берём `*`; если нет и её, разрешено всё. Группы одного агента объединяются |
| Совпадение | `*` — любая последовательность, `$` — конец URL; сравниваются path+query после percent-decoding; решает **самое длинное** правило, при равенстве побеждает Allow |
| `robots.txt` 2xx | разбираем |
| 404 / 410 / прочие 4xx | файла нет, значит разрешено всё (RFC 9309 §2.3.1.3) |
| **401 / 403 / 429** | **не заходим**. RFC разрешил бы, но если сайт не показывает боту даже robots.txt, бота там явно не ждут. Мы строже RFC сознательно |
| 5xx | «недоступен», считаем, что всё запрещено (RFC 9309 §2.3.1.4) |
| нет соединения | сайт недоступен, ни одного запроса к страницам |
| редиректы | до 5, и **каждый переход** проверяется по robots.txt *своего* сайта: `romashka.kz → romashka-group.com` — это другой сайт со своими правилами |
| `Crawl-delay` | не входит в RFC, но распространён на RU-сайтах (его учитывает Яндекс). Уважаем: пауза = max(`REQUEST_DELAY_SECONDS`, `Crawl-delay`), но не больше `MAX_CRAWL_DELAY_SECONDS` (30 с) |

robots.txt кешируется на один запуск и между запусками не переносится.

`RESPECT_ROBOTS=false` существует только для проверки **своего** сайта. При
нём воркер при старте пишет WARNING. Для чужих сайтов не выключайте.

## Вежливость

- **Честный User-Agent**, без маскировки под браузер:
  `qorsa-leadgen-enrich/1.0 (contact enrichment bot; reads public contact pages only; respects robots.txt)`.
  Первое слово — токен, по которому к нам можно обратиться в robots.txt.
  Email в UA нет: `workers/hh` выяснил, что некоторые сервера такой UA
  отклоняют.
- **Паузы.** Между двумя запросами к одному сайту проходит не меньше
  `REQUEST_DELAY_SECONDS` (2 с) или `Crawl-delay`, если он больше. После
  каждого сайта слот тоже ждёт `REQUEST_DELAY_SECONDS`.
- **Параллельность** ограничена семафором: `ENRICH_CONCURRENCY` (5) сайтов
  одновременно, и это *разные* сайты. Один сайт всегда обходится
  последовательно.
- **Мало запросов на сайт:** robots.txt, главная и максимум
  `MAX_CONTACT_PAGES` (3) страниц; обход прекращается, как только найдено
  всё недостающее. В типичном случае это 3 запроса. Адреса вроде
  `/contacts` наугад не перебираются, ходим только по ссылкам самого сайта.
- **Лимиты:** таймаут 15 с; HTML читается не больше `MAX_PAGE_BYTES` (2 МБ);
  не-HTML (PDF, картинки) не скачивается вообще.
- **Одна попытка на компанию.** Ядро помечает её после любого исхода, так
  что один и тот же сайт не обходится каждый день.
- **Скрытое не расшифровываем.** Cloudflare `data-cfemail`, «info [at]
  site [dot] ru», email, который рисует JavaScript: если сайт прячет адрес
  от роботов, это его выбор. Берём только то, что опубликовано открыто:
  `mailto:`, `tel:`, schema.org JSON-LD и видимый текст.
- **Не ходим, куда не надо.** Домены приходят от третьих лиц (работодатель
  на HH сам вписывает `site_url`), поэтому воркер отказывается идти на
  IP-адреса, `localhost`, `*.local`/`*.internal` и на имена, которые
  резолвятся в приватную сеть. Это проверяется на **каждом** редиректе, так
  что внешний сайт не может перенаправить воркер в локальную сеть, например
  на ядро на `:8081`.
- **Соцсети и площадки — не сайт компании.** `vk.com`, `instagram.com`,
  `taplink.cc`, `2gis.kz`, `hh.ru`… (HH часто отдаёт профиль в соцсети
  вместо сайта). Такие домены пропускаются без запросов, иначе мы «нашли»
  бы контакты самого VK.

## Что извлекается и как фильтруется

**Email.** Источники: `mailto:`, JSON-LD (`"email"`), видимый текст.
`<script>`, `<style>` и атрибуты тегов не читаются: там живут DSN Sentry,
счётчики и плейсхолдеры форм (`placeholder="example@mail.ru"`).

Отбрасываются:

| мусор | пример |
|---|---|
| no-reply и служебные | `noreply@`, `no-reply@`, `donotreply@`, `mailer-daemon@`, `postmaster@`, `abuse@` |
| заглушки | `example@…`, `user@example.com`, `name@domain.ru`, `test@test.com` |
| имя файла | `logo@2x.png`, `icon@3x.webp`, `bundle@4.2.min.js` |
| технические id | `3f2a9c1b…@o450123.ingest.sentry.io` |
| хостинг/CMS/сервисы | `@tilda.cc`, `@beget.com`, `@wixpress.com`, `@1c-bitrix.ru`, `@reg.ru`, `@jivosite.com`… |

Приоритет (лучший уходит в ядро):

1. **свой домен**, ящики `info@` > `sales@` > `office@` > `mail@` > `contact@` (затем `contacts@`, `hello@`, `zakaz@`, `order@`);
2. любой другой ящик на **своём** домене (`ivan@romashka.kz`);
3. бесплатная почта (`gmail.com`, `mail.ru`, `yandex.ru`, `bk.ru`…): берём, но в `enrichNotes` пишем «email на чужом домене mail.ru»;
4. чужой корпоративный домен: тоже с пометкой.

«Свой» — это домен из ядра и домен, на который он редиректнул, включая
поддомены (`shop.romashka.kz` ↔ `info@romashka.kz`). При равенстве
`mailto:`/JSON-LD важнее простого текста.

**Телефоны RU/KZ.** `tel:`, JSON-LD (`"telephone"`), видимый текст. Номер
должен начинаться с `+7` или `8` и содержать ровно 10 цифр после префикса,
в любой записи: `+7 (727) 355-10-20`, `8 800 555–35–35`, `+7(4212)12-34-56`,
`89161234567`. Цифры сразу слева или справа делают совпадение
недействительным, поэтому БИН/ИНН/ОГРН/р/с не превращаются в телефоны.
Первая цифра национального номера должна быть 3/4/8/9 (РФ) или 7 (КЗ).
В ядро уходит до 3 номеров через `; `, а какой из них основной, решает
`PhoneUtil`.

**Мессенджеры.** Ссылки `wa.me/…`, `api.whatsapp.com/send?phone=…`,
`whatsapp://`, `t.me/…`, `telegram.me/…`, `tg://resolve`. Кнопки
«Поделиться», инвайты и групповые чаты WhatsApp в расчёт не берутся. Сначала
WhatsApp (это прямая линия), потом Telegram, по одному каждого.

**Кодировки.** Charset из заголовка → `<meta charset>` → UTF-8, а если
кодировка не указана и это не UTF-8, то windows-1251. Заведомо ошибочный
заголовок `ISO-8859-1` от Apache проигрывает `<meta>` страницы.

## Честно: извлечение best-effort

Сайты все разные, и **часть компаний контактов не отдаст**. Это нормальный
исход, а не ошибка:

- **Нет JavaScript.** Сайты на React/Vue/Tilda-виджетах, где контакты
  подгружаются скриптом, для воркера пустые. Headless-браузер сюда
  сознательно не встроен: это на порядок тяжелее и уже совсем не
  «вежливый краулер».
- **Скрытые адреса не расшифровываются** (см. «Вежливость»). Сайты за
  Cloudflare с email-protection email не отдадут, хотя телефон часто отдают.
- **Anti-bot (Cloudflare / DDoS-Guard / Qrator)** отвечает 403 или
  challenge-страницей. Тогда результат будет «главная ответила HTTP 403» или
  «контакты не найдены». Обходить защиту мы не пытаемся.
- **Одна попытка.** Если сайт лежал именно в момент запуска, компания
  всё равно помечена. Повторить можно так:
  ```sql
  update companies set raw = raw - 'enrich_attempted' - 'enrich_at'
  where domain = 'romashka.kz';
  ```
- **Контакты только в картинке или PDF** («прайс и контакты.pdf») не
  извлекаются.
- **Email на чужом домене** может оказаться адресом бухгалтера или
  франчайзи, а не отдела продаж. Поэтому он ставится ниже своего домена и
  всегда помечается.
- **Телефон: KZ-мобильные.** Ядровой `PhoneUtil` классифицирует
  `+7 7xx` (казахстанские мобильные) как `CITY_OTHER`, а не `MOBILE`, и бонус
  +15 «мобильный» они не получают. Это существующее поведение ядра, этот
  воркер его не менял.
- **`base_domain` приблизительный.** Без Public Suffix List «свой / чужой»
  определяется по последним двум меткам (или трём для `com.kz`, `msk.ru` и
  т.п.). Для экзотических зон возможны промахи.
- **DNS-rebinding** не закрыт полностью: имя проверяется при первом
  обращении, а httpx резолвит его ещё раз. От домена, который случайно
  указывает в локальную сеть, это защищает. От целенаправленной атаки с
  быстро меняющимся DNS — нет.

Сколько контактов реально находится, зависит от выборки и заранее не
известно. Живой прогон по базе на момент написания не делался: весь HTTP в
тестах на моках (см. ниже). Первый реальный запуск покажет долю
`found / nothing_found / unavailable / robots_blocked` в итоговой строке
`ENRICH: …`.

## Setup

```bash
cd workers/enrich
cp .env.example .env
python -m venv .venv
.venv/Scripts/activate    # или `source .venv/bin/activate`
pip install -r requirements.txt
```

```bash
# из корня репозитория, при запущенном ядре на :8081
python -m workers.enrich.main
```

| переменная | по умолчанию | что делает |
|---|---|---|
| `CORE_URL` | `http://localhost:8081` | ядро |
| `ENRICH_BATCH` | `50` | компаний за один `GET /pending-enrich` |
| `MAX_BATCHES_PER_RUN` | `10` | сколько таких пачек за запуск; очередь обычно кончается раньше |
| `ENRICH_CONCURRENCY` | `5` | сайтов одновременно |
| `REQUEST_DELAY_SECONDS` | `2.0` | пауза между запросами к одному сайту и между сайтами |
| `MAX_CRAWL_DELAY_SECONDS` | `30` | потолок для `Crawl-delay` из robots.txt |
| `REQUEST_TIMEOUT_SECONDS` | `15` | таймаут запроса |
| `RESPECT_ROBOTS` | `true` | **не выключать** для чужих сайтов |
| `USER_AGENT` | см. выше | имя + назначение |
| `MAX_CONTACT_PAGES` | `3` | страниц «Контакты/О нас» после главной |
| `MAX_PAGE_BYTES` | `2000000` | обрезка больших страниц |
| `RUN_ONCE` | `true` | один проход и выход (для планировщика) |
| `LOOP_INTERVAL_MINUTES` | `60` | пауза между проходами при `RUN_ONCE=false` |

Ключей и токенов у воркера нет. Всё, что нужно, — это URL ядра.

## Контракт с ядром

`GET /api/v1/companies/pending-enrich?limit=50` → `[{id, name, domain, email, phone, messenger, city}]`.
Условие: `domain` не пуст **и** (`email` пуст **или** `phone` пуст) **и** нет
`raw.enrich_attempted=true`. Сортировка: score лида по убыванию, затем
старые первыми. `limit` зажимается в 1..500.

`PATCH /api/v1/companies/{id}/contacts`, тело:
```json
{"email": "info@romashka.kz",
 "phone": "+77273551020; +77012345678",
 "messenger": "https://wa.me/77012345678",
 "enrichNotes": "email с /kontakty/; телефон с главной"}
```
Все поля необязательны; пустое тело `{}` — валидный отчёт «пробовали, ничего нет».
Ответ: `{companyId, filled: ["phone"], email, phone, messenger, score, status, hotReason}`,
где `filled` — поля, которые **реально записаны**. Значение для поля,
которое уже было заполнено, игнорируется и в `filled` не попадает. Ответы:
404 для неизвестного id, 400 с разбором по полям для невалидного email или
слишком длинных значений.

## Tests

```bash
pip install -r requirements.txt
pytest workers/enrich/tests
```

Всё офлайн: без сети, без ядра, без реальных пауз.

- `test_extractor.py` — разбор на фикстурах `tests/fixtures/*.html`:
  искусственные страницы, собранные по образцу реальных Bitrix/Tilda-страниц
  «Контакты» и главных, с настоящим мусором рядом с настоящими контактами
  (no-reply в форме, плейсхолдеры, DSN Sentry, `logo@2x.png`, адрес
  техподдержки конструктора, реквизиты с длинными числами). Компания, домен и
  номера выдуманы, реальных персональных данных там нет. Отдельно проверяются
  фильтр мусорных email, приоритет своего домена, форматы телефонов RU/KZ,
  «не телефоны», мессенджеры, поиск ссылок на контакты, windows-1251.
- `test_robots.py` — RFC 9309: группы, longest-match, `*`/`$`,
  percent-encoding, Crawl-delay, смысл каждого статуса robots.txt.
- `test_fetcher.py` — robots.txt перед каждым запросом и на каждом
  редиректе, кеш по origin, паузы и Crawl-delay, UA, отказ идти в локальную
  сеть, обрезка тела, не-HTML, таймауты.
- `test_enricher.py` — сценарий целиком на фейковом сайте: нашли и сказали
  откуда; Disallow на `/kontakty/` (страница **не запрашивается**); Disallow
  на всё; недоступный сайт, таймаут, fallback на http, 503, соцсети,
  редирект в локальную сеть.
- `test_runner.py` — PATCH уходит всегда (в том числе при «ничего не
  найдено», недоступном сайте и падении парсера), нет зацикливания,
  семафор ограничивает параллельность, пауза после каждого сайта.
- `test_core_client.py`, `test_domains.py` — контракт с ядром, ретраи,
  чистка доменов, guard.

Java-сторона: `ContactEnrichmentServiceTest` (не перетирает, флаг ставится
всегда, PhoneUtil и пересчёт score) и `EnrichmentControllerIT` (реальный
Postgres в Testcontainers: выборка pending, PATCH, 404/400).

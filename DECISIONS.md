## Решения — по приоритету

### 1. Аудит сайтов — построен, упирается в ключ PSI

**Сделано.** `workers/site_audit/` написан и прогнан вживую по всем 185
доменам: 137 измерено, 48 мертвы, 0 ошибок. Заглушки в `ScoringService`
сняты, добавлены `GET /companies/pending-audit` и
`PATCH /companies/{id}/audit`. Порог `audit-fails-threshold` откалиброван
по факту: 10 → 2 (137 сайтов дали 0-8 провалов, основная масса 1-3, старое
значение не сработало бы никогда). 36 компаний прошли порог, 11 лидов
перешли NEW → QUALIFIED.

**Чего это не дало.** HOT так и 6. Арифметика: OSM-компания с сайтом
набирает максимум 25 (контакт+гео 10 + мобильный 15), плюс `auditFails` 20
— это 45. До порога 70 не хватает ровно `pagespeed +30`.

**Что осталось.** Ключ PageSpeed Insights. С ним тот же лид даёт 75 и
становится горячим. Локальный зонд без ключа до этого не дотягивает
принципиально, сколько проверок в него ни добавляй.

PSI — это НЕ Places: бесплатен, 25 000 запросов/день, активация биллинга
не нужна, история с `Your free trial requires a prepayment` его не
касается. Включить «PageSpeed Insights API» в Google Cloud, создать ключ,
вписать `PSI_API_KEY` в `workers/site_audit/.env`, перезапустить воркер со
сброшенным флагом:

```sql
update companies set raw = raw - 'audit_attempted';
```

Без ключа воркер тоже работает — просто отдаёт только `auditFails`.

### 2. Sheets — 5 минут, и лиды видно

**Проблема.** `SHEETS_SPREADSHEET_ID` пустой, ядро стартует с WARN
«Sheets export disabled». 692 лида лежат только в Postgres.

**Рекомендация.** Создать таблицу, расшарить её на email сервис-аккаунта
из `credentials/google.json` (поле `client_email`) с правом
редактирования, id из URL вписать в `.env`. Перезапуск ядра — и
автосинк раз в 5 минут.

### 3. Docker Desktop — подтвердить тесты

**Проблема.** 83 теста, 79 зелёных. Четыре интеграционных
(`LeadRepositoryTest`, `AdminControllerIT`, `EnrichmentControllerIT`,
`IngestControllerIT`) падают с «Could not find a valid Docker
environment». На версию Testcontainers больше не ругается — значит
несовместимость с Engine 29 ушла, но подтвердить это можно только
запуском.

**Рекомендация.** Docker Desktop лежит в
`C:\Users\user\AppData\Local\Programs\DockerDesktop\`, WSL-дистрибутив
`docker-desktop` в статусе Stopped. Поднять руками (из-под MCP не
стартует), прогнать `mvn test`. Флаг `-Dapi.version=1.44` больше не
нужен.

### 4. `workers/instagram_cta/` — решить судьбу

**Проблема.** Папка лежит untracked. Я её не коммитил (харвест
комментаторов — персданные физлиц, ты сам так решил) и не удалял
(untracked-файлы git не вернёт). Значение `INSTAGRAM_CTA` в enum и его
хуки в скоринге/экспорте закоммичены отдельно и безвредны.

**Рекомендация.** Закоммитить в ветку и убрать из рабочего дерева:

```powershell
git checkout -b wip/instagram-cta
git add workers/instagram_cta/
git commit -m "wip: instagram CTA worker, not for main - see DECISIONS.md"
git checkout main
Remove-Item workers\instagram_cta -Recurse -Force
```

Код не потерян, дерево чистое, к Ad Library вернёшься с готовой
обвязкой. Enum-значение переиспользуется как есть.

### 5. `ADMIN_ENABLED=true` — снять

**Проблема.** Ядро сейчас запущено с этой переменной. `POST
/api/v1/admin/rescore` перезаписывает все лиды, `DELETE
/api/v1/admin/demo-data` удаляет данные. Аутентификации перед ними нет —
это kill-switch, а не защита.

**Рекомендация.** Включать переменную точечно, только на время
пересчёта после правки весов. В обычном режиме — не задавать.

### 6. Ротация засвеченных ключей

Из HANDOFF: пароль amoCRM, ключ 2GIS, Google API key, Telegram
`api_hash`.

**Рекомендация по порядку.** Сначала Telegram `api_hash` и пароль
amoCRM — это доступ к живым аккаунтам, а не к платным квотам. 2GIS и
Google API можно и позже: 2GIS всё равно демо-тариф без
`contact_groups`, Google без биллинга не работает. Под парсинг Telegram
завести отдельный аккаунт, как и планировал.

Проверено: в git секреты не утекли. `credentials/*.json`, `*.session`,
`.env`, `workers/hh_apply/session/` все в `.gitignore`, `git ls-files`
чист. `leadgen_session.session` в корне не закоммичен.

### 7. Telegram-воркер — самый горячий источник, стоит на месте

**Проблема.** Код готов (anti-hiring фильтр, channel_rater,
дизайн-ключевики), но аккаунт словил FloodWait при резолве 98 каналов.

**Рекомендация.** Сначала кэш resolved-каналов — он устраняет FloodWait
навсегда, промт под него уже был согласован. Потом урезать `channels.yml`
до 10-15 реально подписанных. Подписываться руками, по-тихоньку, с
отдельного аккаунта. Прокси-ротацию не трогать — сам просил.

### 8. Расписание вместо ручных запусков

**Проблема.** Всё гоняется руками. OSM прошёл 25 пар из 2010 — при
50 парах за прогон это 40 прогонов до полного цикла.

**Рекомендация.** Task Scheduler: OSM каждые 2-3 часа (упирается в
`TARGET_PER_DAY=300` и в лимиты Overpass — публичные зеркала весь день
отдавали 429/504, чаще смысла нет), zakupki раз в сутки, enrich через
час после zakupki. Ядро — автозапуск при входе.

## Куда не вкладываться

- **`workers/hh/`** — HH закрыл `/vacancies` для анонимов, нужен
  OAuth-токен, заявка на dev.hh.ru требует регистрации компании
  работодателем и модерации до 15 рабочих дней. Ждать, не трогать.
- **`workers/twogis/`** — демо-ключ не отдаёт `contact_groups`,
  проверено вживую. Без платного тарифа источник бесполезен.
- **`workers/google_places/`** — Places требует предоплаты для
  активации биллинга. Ключ есть, толку нет.
- **`workers/newdomains/`** — нужна оплата фида WhoisXML, и код ни разу
  не видел живого ключа: после оплаты почти наверняка потребует правок
  под реальный формат ответа. Не платить, пока нет потребности.
- **`workers/hh_apply/`** — не источник лидов, это твой личный агент
  откликов. Разблокируется двумя командами, когда понадобится:
  `python -m workers.hh_apply.login --enter` (вход руками в окне),
  затем `python -m workers.hh_apply.probe --from-search`.

## Что стоит знать про воронку

**HOT бывают только из закупок.** Все шестеро горячих — госзаказчики со
счётом 80 и одинаковым набором: прямой интент + бюджет + контакт/гео +
мобильный. Это следствие модели: `direct_intent +35` есть только у
telegram / vacancy / avito_job / zakupki, а из них работают пока одни
закупки. Пока Telegram стоит, а аудита сайтов нет, воронка держится на
одном источнике.

**Закупки перестали давать новые компании.** Последний прогон отправил
300 извещений, новых компаний в базе ноль — все схлопнулись в уже
известных заказчиков. Это не дефект дедупа: одна администрация публикует
десятки закупок, компания одна. Рост базы по этому источнику будет
медленным и упрётся в число госзаказчиков, а не в число извещений.

**Enrich работает, но потолок не поднимает.** 170 компаний, контакты у
103 (email 85, мессенджер 69, телефон 23), ошибок 0, robots.txt закрыл
7 сайтов. Ни один лид при этом не сменил статус: контакт даёт максимум
`контакт+гео +10` и `мобильный +15`, а у этих компаний есть сайт —
значит упираются в те же 25. Ценность enrich не в скоре, а в том, что
теперь есть куда писать.

## Instagram: разворот на Ad Library упирается в то же самое

Исходный замысел — собирать комментаторов под ключевым словом — закрыт
сознательно: персданные физлиц под 152-ФЗ, неофициальный API против ToS
Meta, и человек в комментариях поднял руку не тебе, а другому
рекламодателю.

Разворот на рекламодателей через Meta Ad Library выглядел как чистое
решение, но у него есть та же проблема с другой стороны: **официальный Ad
Library API отдаёт только политическую и социальную рекламу.**
Коммерческие объявления видны в веб-интерфейсе, но программного доступа к
ним нет — то есть «собирать рекламодателей автоматически» снова означает
скрейпинг против ToS.

Варианты, которые остаются честными:

- **Руками.** Ad Library ищется по стране и ключевому слову в браузере.
  Двадцать минут раз в неделю дают список рекламодателей нужной ниши,
  дальше их домены идут в обычный `ingest` и проходят через `site_audit`.
  Медленно, но это именно те компании, которые платят за трафик.
- **Через сайты рекламодателей.** Тот, кто крутит рекламу, почти всегда
  ставит пиксель Meta. Проверка наличия `fbq(` или `connect.facebook.net`
  на главной — это +1 проверка в `site_audit`, не новый источник, и она
  даёт ровно нужный сигнал: «платит за рекламу». Стоит обсудить как
  отдельный вес в скоринге.

Второй вариант я бы и рекомендовал: он переиспользует уже построенный
воркер, не требует ключей и не трогает чужие персданные.
